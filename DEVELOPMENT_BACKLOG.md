# Development Backlog

Рабочий backlog для реализации следующих версий `Tiff-To-PNG` как production-инструмента для CG-художников.

`ROADMAP.md` отвечает на вопрос "куда идем".
Этот документ отвечает на вопрос "что именно делаем дальше".

## Принцип Работы

- идем версиями, а не расползаемся по всем фичам сразу
- каждая версия должна давать ощутимую пользу художнику
- сначала закрываем ядро и UX, потом сложные pipeline-фичи
- каждая задача должна иметь понятный результат в интерфейсе или сервисном слое

## v0.2 - Asset Intake And Queue

Цель версии:
превратить текущий batch-конвертер в удобный инструмент для загрузки, просмотра и запуска набора текстур.

### Epic 1. Очередь файлов

- [ ] добавить доменные модели очереди:
  `QueueItem`, `QueueStatus`, `AssetKind`, `AssetMetadata`
- [ ] добавить сервис сканирования файлов и папок с извлечением базовых метаданных
- [ ] отделить режим "обработка папки" от режима "обработка явного списка файлов"
- [ ] поддержать удаление элементов из очереди до запуска
- [ ] поддержать очистку всей очереди

Ожидаемый результат:
пользователь видит, что именно будет обработано, а не запускает конвертацию вслепую.

### Epic 2. Drag-and-drop

- [ ] включить `drag-and-drop` файлов и папок в главное окно
- [ ] поддержать дроп как в окно целиком, так и в область очереди
- [ ] автоматически разворачивать папки в список поддерживаемых файлов
- [ ] игнорировать неподдерживаемые форматы с понятным сообщением в логе

Ожидаемый результат:
художник просто перетаскивает текстуры в окно без выбора через диалоги.

### Epic 3. Таблица задач

- [ ] заменить "слепой запуск" на видимую таблицу задач
- [ ] вывести колонки:
  `Имя`, `Тип`, `Размер`, `Разрешение`, `Статус`, `Выходной путь`
- [ ] добавить статусные состояния:
  `Pending`, `Ready`, `Running`, `Done`, `Skipped`, `Error`
- [ ] подсветить ошибки и предупреждения цветом
- [ ] синхронизировать лог и строку состояния с выбранным элементом очереди

Ожидаемый результат:
у пользователя появляется диспетчер задач, а не просто форма настроек.

### Epic 4. Минимальный preflight-анализ

- [ ] до старта считывать базовые свойства изображения:
  размер, формат, альфа, mode
- [ ] помечать предупреждения:
  слишком большой размер, неподдерживаемый формат, пустой файл, сомнительный alpha
- [ ] отображать предупреждения прямо в очереди

Ожидаемый результат:
ошибки видны до запуска, а не только после него.

### Definition Of Done

- можно добавить файлы мышью или `drag-and-drop`
- пользователь видит список задач до запуска
- можно удалить отдельные элементы и очистить список
- статусы обновляются во время выполнения
- неподдерживаемые файлы не ломают batch

## v0.4 - Production Features

- [ ] реализовать сборку packed-textures:
  `ORM`, `RMA`, `MRA`
- [ ] дать возможность выбрать, какая карта идет в какой канал
- [ ] показывать отсутствующие карты до запуска

Ожидаемый результат:

  `sRGB` для color maps, `Linear` для technical maps
- [ ] привязать эти правила к автоопределению типа карты
- [ ] выводить предупреждение, если карта выглядит как technical map, но названа как color map

Ожидаемый результат:
уменьшается шанс человеческой ошибки при подготовке текстур.

### Epic 3. Texture Validation

- [ ] добавить полноценный preflight validator
- [ ] проверять:
  `power-of-two`, `CMYK`, alpha, oversized textures, naming mismatch
- [ ] ввести уровни:
  `Info`, `Warning`, `Error`
- [ ] экспортировать отчет в `.txt` или `.csv`

Ожидаемый результат:
приложение становится не только конвертером, но и QC-инструментом.

### Epic 4. Export Profiles

- [ ] добавить профили экспорта:
  `Unreal`, `Unity`, `Blender`
- [ ] привязать к ним naming rules, packed maps и ограничения размеров

Ожидаемый результат:

### Definition Of Done

## Что Не Делаем Пока

Чтобы не расползтись по объему слишком рано, пока не берем в работу:

- плагинную систему
- интеграции с `Blender`, `Substance`, `Unreal`
- watch folders
- многопоточную scheduler-систему
- full parity между `CLI` и `GUI`

Сначала делаем сильный `MVP`, потом усиливаем pipeline-слой.
