# Tiff-To-PNG

Модульное приложение на `PyQt6` для пакетной конвертации изображений в PNG.
Входные форматы включают `DDS`, `PNG`, `TIFF`, `TGA`, `JPEG`, `BMP`, `GIF`, `WEBP` и `PSD`.
Для игровых воркфлоу уже есть packing-профили `ORM`, `RMA`, `MRA`, `Unity URP` и `Unity HDRP`.
Packed-текстуры можно напрямую перепаковывать между этими схемами без предварительной ручной распаковки.
Системный сценарий `Traditional / Non-Packed Workflow` раскладывает packed-входы
в отдельные PBR-карты для Offline / Production.
Блок `Итоговый Texture Set` показывает предусмотренные выбранным пайплайном файлы,
их suffix и packed channel mapping. После добавления очереди он отдельно отмечает
доступные outputs и карты, для которых не хватает исходных данных.

Автоопределение packed layout работает по стандартным suffix: `*_orm`, `*_arm`, `*_rma`,
`*_mra`, `*_metallicsmoothness`, `*_metallicglossmap` и `*_maskmap`. Для нестандартного
имени layout можно вручную выбрать в `Asset Inspector -> Map Type` как `Packed ...`.

## Требования

- Windows
- Python 3.11+ 

## Создание виртуального окружения

Если окружение еще не создано:

```powershell
cd d:\Python\Tiff-To-PNG
python -m venv .venv
```

## Установка зависимостей

### В существующее окружение `.venv`

```powershell
cd d:\Python\Tiff-To-PNG
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Если `pip` упирается в SOCKS-прокси

На некоторых системах `pip` подхватывает системный `socks5` proxy. Тогда установку лучше выполнять так:

```powershell
cd d:\Python\Tiff-To-PNG
$env:NO_PROXY='*'
$env:no_proxy='*'
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Активация окружения

При желании можно активировать окружение перед запуском:

```powershell
cd d:\Python\Tiff-To-PNG
.\.venv\Scripts\Activate.ps1
```

Если PowerShell блокирует активацию:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

## Запуск приложения

### GUI

```powershell
cd d:\Python\Tiff-To-PNG
.\.venv\Scripts\python.exe tiff_to_png.py
```

Приложение автоматически сохраняет последние пути, параметры конвертации и размер окна
в `app_settings.json` в пользовательской папке приложения
(`%LOCALAPPDATA%\TexturePipelineWorkbench` на Windows). Там же находятся пользовательские
пресеты `conversion_presets.json`. При первом запуске старые файлы рядом с EXE или
в корне репозитория копируются в эту папку, если пользовательской копии ещё нет.
Старые файлы не удаляются. Сцены сохраняются по выбранному пользователем пути.

Сцены, настройки и пресеты записываются через временный файл с атомарной заменой.
Неизвестная версия сцены или неизвестный тип ноды отклоняются с сообщением об ошибке,
без подмены нод или изменения текущей сцены.

Перед batch-конвертацией проверяется общий план обычных и packed-файлов.
Если разные задачи получают один выходной путь или перезапись изменит ещё нужный
исходник, весь запуск останавливается до записи файлов с перечнем конфликтов.
`Overwrite` не отключает эту защиту. Выберите отдельную папку результата или
устраните неоднозначные имена. Безопасная обработка на месте сохранена; при
частичной ошибке распаковки общий packed-исходник больше не перезаписывается.
Обычные и packed PNG сохраняются атомарно через временный файл в той же папке.
Это защита каждого файла, а не транзакция с откатом всего набора.

Кнопка `Layout` в Graph Workbench учитывает подключения и порядок портов:
цепочки идут слева направо, короткие ветки размещаются ближе к потребителю,
независимые сети разделяются. Учитываются реальные размеры нод; повторное
нажатие не сдвигает уже разложенный граф. Действие отменяется через Undo.
Для длинных проводов резервируется место, но это не полноценная трассировка:
в сложных сетях пересечения всё ещё возможны. Связи и параметры нод не меняются.

### Производительность графа

В `Graph Workbench` откройте вкладку `Performance` в панели `Node Properties`.
Она показывает последний завершённый расчёт preview: собственное время каждого
выхода (`Self ms`), время вместе с upstream-веткой (`Branch ms`), попадания/промахи
кэша (`Cache H/M`), рабочее разрешение и число вызовов. Строки отсортированы по
собственному времени; двойной щелчок выделяет соответствующую ноду.

Время веток нельзя складывать: в них повторно учитываются входные вычисления.
Строка `preview` относится к финальной сборке результата. Это CPU wall time,
включая загрузку и копирование изображений, но без GPU upload/draw. При новом
расчёте предыдущий отчёт помечается как устаревший; смена сцены очищает его.

Для диагностики самого PBR Preview включите `Timings` рядом с `Reload Maps`.
Две строки под превью показывают CPU-время последнего upload и число обновлённых
карт, CPU-время отправки draw и GPU-время его исполнения. Upload включает
PIL → QImage, вызовы GL и создание mipmaps; это **не** отдельное измерение
GPU upload. При включении после загрузки материала upload будет `—` до следующего
обновления карт. Подробности и размеры текстур/viewport доступны в tooltip.

GPU-результат читается асинхронно, только после готовности, без `glFinish`.
Замеры выключены по умолчанию, выполняются не чаще 10 раз в секунду и не создают
постоянного цикла перерисовки. Без поддержки timer queries сохраняются CPU-замеры,
а GPU показывает `n/a`. CPU и GPU времена перекрываются: их нельзя складывать
или переводить в FPS; Qt composition, swap и VSync сюда не входят.

PBR Preview переиспользует неизменившиеся GPU-карты: изменение Roughness или AO
обновляет только properties texture. Переключение normal convention меняет
шейдерный параметр без повторной загрузки карт. После сброса кэша или смены
разрешения соответствующие текстуры загружаются заново.

CPU-сборка также переиспользует неизменившиеся карты. Готовые Normal/Emissive и
properties сохраняются в общем LRU-кэше; при нехватке места они удаляются раньше
результатов входных нод. Это сокращает копирования и конвертации при работе со
слайдерами, не меняя результат обработки.

Замер upload на текущей видеокарте (из корня репозитория):

```powershell
.\.venv\Scripts\python.exe -m tools.benchmark_pbr_upload --sizes 256 1024 --iterations 15
```

Это отдельный тест с невидимой native OpenGL surface; он проверяет сохранение
GPU-объектов и mipmaps, не меняет сцены/настройки. Замер не включает вычисление
графа и draw; используемый для измерения `glFinish` отсутствует в рабочем preview.

Проверка `Timings` на реальном OpenGL-контексте, включая повторное включение,
смену материала с незавершённым замером и освобождение ресурсов:

```powershell
.\.venv\Scripts\python.exe -X faulthandler -m tools.check_pbr_timing
```

Отдельный CPU-замер на синтетическом прогретом графе:

```powershell
.\.venv\Scripts\python.exe -m tools.benchmark_pbr_cpu --sizes 256 1024 2048 --iterations 15
```

### CLI

Пример запуска из командной строки:

```powershell
cd d:\Python\Tiff-To-PNG
.\.venv\Scripts\python.exe tiff_to_png.py .\input --out .\output --recursive
```

## Полезные параметры CLI

- `--out` — выходная папка
- `--recursive` — обработка подпапок
- `--force-rgba` — принудительный режим `RGBA`
- `--overwrite` — перезапись существующих `PNG`
- `--delete-source` — удалить исходник после успешной конвертации
- `--resize-percent` — масштабирование в процентах
- `--max-side` — ограничение длинной стороны
- `--png8` — сохранить как `PNG-8`
- `--pack-layout` — собрать или перепаковать в `orm`, `rma`, `mra`, `unity_urp` или `unity_hdrp`
- `--unpack-packed` — распаковать распознанные packed-текстуры в отдельные карты

CLI возвращает `0` при успешном выполнении (включая обычные пропуски), `1` при ошибках
конвертации или packing, `2` при некорректном запросе.
При конвертации с packing удаление успешно обработанных исходников откладывается
до завершения packing. Если packing завершился ошибкой, был пропущен или не нашёл
заданий, исходники сохраняются. `Pack Only` сам по себе не удаляет исходники.

Полная справка:

```powershell
.\.venv\Scripts\python.exe tiff_to_png.py --help
```
